# Шароломка — спецификация

Живой документ: описывает, **как игра должна работать** и **почему так решено**.
Меняешь поведение — обнови этот файл в том же коммите. Если код и спека расходятся,
это баг одного из них: выясни у владельца (Антон), что верно.

Движок: Godot 4.3, GDScript, рендерер GL Compatibility. Платформы: Android (главная), Windows, Linux.
Язык интерфейса и комментариев в коде — русский.

---

## 1. Суть игры

2D-idle-арканоид. Игрок выпускает шарики, они сами летают и разбивают квадраты.
За каждую снятую с квадрата жизнь начисляется 1 монета. На монеты покупаются новые шары
и прокачка урона/скорости. В некоторых квадратах спрятаны U-баллы — на них открываются
новые типы шаров и перки. Карты огромные, стены-картинки из белых кубиков, туман войны.

## 2. Экран игры

```
┌─────────────────────────────────────┐
│ [≡] [● 4.7K] [U 7]  Разбито 2% ▬▬  [∠ 45°] │  ← верхняя полоса
│                                     │
│            карта (камера)           │
│                                     │  ← без прицеливания на карте только шары, никаких меток
│                                     │
├─────────────────────────────────────┤
│ [● ×2 · 46] [● ×0 · 300] …          │  ← выбор типа: число шаров и цена следующего (нет денег — тусклее)
│ [↺ Сброс]            [↑ Прокачка]   │
└─────────────────────────────────────┘
```

- **Выстрел рогаткой** (основной способ): нажать на карту, **подержать 0.22 с** (вокруг пальца дорисовывается
  колечко, в момент начала прицела — короткая вибрация) и оттянуть палец назад — шар выбранного типа
  покупается и летит в противоположную сторону **ровно из точки нажатия** (сдвиг только на ≤ 8.5 px от соседней
  стены/квадрата, чтобы шар не появился внутри). Нажали на квадрат/стену/туман — красный круг
  «Нажмите на открытую клетку», выстрела нет (раньше точка подтягивалась к соседней клетке — рогатка была «кривой»).
  Не хватает монет — красный круг «Не хватает монет»; как только монет хватает, стрелка сразу жёлтая и отпускание
  стреляет (без лишнего движения пальца). Отмена — только вытягивание за круг; деньги и точка вылета проверяются
  каждый кадр (`_sling_blocked`). Пока тянешь: вокруг точки нажатия круг —
  область наведения (радиус 230 px), от точки выстрела — стрелка направления (длиннее при сильнее оттянутом),
  над кругом подсказка «Отпустите — выстрел». Стрелка рисуется от точки вылета. Вытянул палец за круг — всё красное, «Отпустите — отмена»,
  отпускание ничего не делает и возвращает прежнее направление. Оттягивание короче 28 px — не выстрел.
- **Кнопки «Выстрел» нет** — стрельба только рогаткой. Никаких меток на карте вне прицеливания.
- **Сброс** — переключатель (подсвечен, «Сброс: прицельтесь»): следующий выстрел рогаткой не покупает шар,
  а бесплатно перезапускает из точки нажатия шар выбранного типа, заработавший меньше всех с прошлого сброса
  («бездельника»); стрелка и подсказка голубые — «Отпустите — перезапуск бездельника». После перезапуска —
  кулдаун 30 с на тип («Сброс · 28 с»). Повторное нажатие выключает режим.
- **Угол** (кнопка справа вверху): «любой» / «45°» (всегда кратно 45°) / «ключевые» — к углам, кратным 45°, прицел
  притягивается только вблизи: ±N°, N = 1–5 (ползунок «Залипание к ключевым углам» в настройках, по умолчанию ±2°:
  43…47° → 45°). Режима 90° нет с v0.23.
- **Подпись угла** у кончика стрелки при прицеливании: как на транспортире (0° вправо, 90° вверх, 0…359°);
  на ключевом угле (кратном 45°) — золотая.
- **Прокачка** — полупрозрачное окно поверх карты, игра под ним продолжается. Вкладки «Шарики» и «Перки».
- Кнопки не прижимаются к краям: учитывается safe area (вырез, скругления, системные полосы) + 20 px.

### Управление
| Жест | Действие |
|---|---|
| Один палец: нажать и сразу вести (сдвиг > 12 px раньше 0.22 с) | перемещение карты |
| Один палец: нажать, подержать 0.22 с, оттянуть | рогатка — выстрел в сторону, противоположную оттягиванию; за кругом — отмена |
| Один палец: короткое касание | ничего |
| Два пальца | масштаб (щипок) и перемещение карты; второй палец отменяет начатый жест |
| ПК: левая кнопка (так же, как палец) / колесо / правая кнопка | перемещение или рогатка / масштаб / перемещение |
| Кнопка «Назад» Android | закрыть прокачку → в меню → выход |

### Камера
- Центр поля может дойти до любого края **открытой** части карты при любом масштабе
  (ограничение по центру, а не по краю экрана — иначе до края не добраться без сильного увеличения).
- Масштаб: самый мелкий — вся открытая часть на экране (но не крупнее 30 px на клетку),
  самый крупный — 100 px на клетку (zoom 2.5). Стартовый — 52 px на клетку.
- Пол рисуется только под видимыми клетками; туман — фон сцены. Вблизи (≥24 px на клетку) на полу
  еле видная сетка (белый, прозрачность 5.5%), в тумане — ещё прозрачнее (3%).
- **Мягкий край тумана**: скрытые клетки у границы освещены градиентом на 2 клетки (свет в вершинах сетки по
  расстоянию до открытых клеток: 55% → 19% → 0 цвета пола) — туман не обрывается ступенькой. Треугольники края
  кэшируются в куске (`fog_*`) и пересчитываются только при открытии клеток рядом (в т. ч. в соседнем куске), так что
  перерисовка после ударов не дорожает; весь край куска — одна команда `canvas_item_add_triangle_array`.
- **Граница карты**: голубая рамка с мягким ореолом поверх кусков; за пределами карты — темнее тумана.
  Отдалиться можно до **всей карты целиком** (даже 10000×10000) — видны её границы и размер; центр камеры
  по-прежнему ограничен открытой частью. (В v0.18 на больших картах граница не попадала в кадр.)
  Слои сетки в тумане и границы перерисовываются только при движении камеры.
- Уровни детализации по размеру клетки на экране: ≥24 px — квадраты с цифрами жизней и объёмом;
  4–24 px — «свет»: только цвет; <4 px — каждый кусок 32×32 рисуется одной текстурой (пиксель = клетка).
- Шарик на экране не меньше 11 px.

## 3. Мир

- Клетка = 40 мировых единиц. Типы клеток: 0 пусто, 1 квадрат, 2 стена (белый кубик), 3 за краем карты.
- **Прохождение начинается из центра карты** (`start = (W/2, H/2)`), вокруг старта пустой круг радиусом 2.3 клетки.
- **Жизни квадрата** = `ceil(hp_base · (1 + d · hp_growth)^1.6)`, где d — расстояние от старта в клетках.
- **Туман войны**: видны только клетки первого слоя — соседи (8 направлений) пустых клеток.
  Всё дальше (квадраты, стены, U-баллы) скрыто. Когда квадрат разбит, открываются его соседи.
  Инвариант: каждая пустая клетка видна; каждая видимая клетка соседствует с пустой.
- **U-баллы** спрятаны в квадратах (см. §3а), определяется хешем координат — ничего не хранится.
- **Золотые квадраты**: 0.3% квадратов (+20% за уровень «Золотых квадратов»), видны золотыми с белой рамкой.
  Разрушение — «золотая лихорадка»: урон всех шаров ×2 на 15 с (+3 с за уровень «Наследия»; копится до двух).
  Под верхней панелью — убывающая золотая полоска «Урон ×2 · 12 с» (белый текст с тёмной обводкой — читается
  и на золотой, и на тёмной части); она и всплывающие сообщения лежат
  **под** окном прокачки (в v0.19 сообщение рисовалось поверх окна).
- **Финал маленькой карты** (карты, проходимые на 100%): когда осталось ≤ 8% квадратов (минимум 12), оставшиеся
  открываются, а шары каждые 0.25 с поворачивают по полю расстояний (обход в ширину от оставшихся квадратов
  по свободным клеткам) — так они обходят стены картинок. Без этого последние минуты уходили на поиск
  разрозненных квадратов (на «Сердце» — 5 минут без покупок).
- **Стены-картинки**: контур шаблона растеризуется в белые неразрушаемые кубики без диагональных щелей.
  Внутри — полость из квадратов. Со стороны старта прорубается вход шириной 3 клетки в самую большую
  связную часть полости. Всё, куда шарик не может долететь, заливается стеной.
  Картинка целиком помещается в карту (регионы у края карты обрезаются).
- Шаблоны (19): домик, сердце, звезда, луна, ёлка (+звезда), кот, рыба, клубок, гриб, гора, кактус, снежинка, ракета,
  корона, замок, кристалл, цветок, капля, молния (`scripts/maps.gd → templates()`); у каждого есть полость с входом
  (проверяется тестом).

- Меню показывает открытые уровни и следующий закрытый, прокручивается пальцем (в т. ч. с кнопки «Играть»)
  и при открытии прокручивается к текущему уровню.
- Карты ≤ 60 000 клеток генерируются целиком и проходятся на 100% (диалог «Победа!», сохранение удаляется).
- Выполненная цель уровня: ★ (см. §3а), открывается следующий уровень. На больших картах после цели игра продолжается.

  толщиной в клетку (граница закрашенных областей). Маски собираются заранее: `tools/render_svg.gd` (SVG → PNG через

  3 клетки (кратчайший путь сквозь стены от старта). Размеры 520×640…720×720, бесконечные — 600×720.
  Старт — у нижнего края, поэтому рост жизней вдвое меньше прежнего (0.015 / 0.01 / 0.0075, бесконечные 0.0075),
  цели по симулятору (v0.41.1): «Космодром» 110 тыс. (бот ~29 мин), «Гавань» 110 тыс. (~26), «Обсерватория»
  130 тыс. (~31), бесконечные — от 120 тыс. +5% за уровень (~25 мин).
  Формат сохранения карт — ver 8. Тест `test_picture_maps`.
  **Полная расчистка большой карты** (с v0.42): число квадратов картины известно из маски (`full_tracked`), прогресс
  идёт от цели (может быть >100%), а при выполнении цели подсказка «Расчистите карту целиком — ещё +N ★». Финал —
  на последнем 1% квадратов (не больше 2000): досоздаются все куски, оставшиеся квадраты проявляются, шары ведёт
  поле расстояний, которое считается порциями по 40 тыс. клеток за кадр (без паузы на полмиллиона клеток).
  Полная расчистка — ★ (первый раз как за цель, потом +1; `GameData.maps_full`) и «Победа». Тест `test_big_map_full_clear`. Процедурные раскладки больше не используются.
- **Карты-сцены (с v0.29)** — рисунок тонкими белыми линиями, как в pixel-rikoshet, но свои сюжеты (`map["scene"]`,
  `game.gd → _build_scene`). Форма карты `shape`: `oval` / `circle` / `round` (скруглённый прямоугольник); снаружи
  формы — сплошная стена, которая рисуется цветом фона за картой (`_void_at`), граница идёт по контуру формы, а за
  формой — затемнение одним массивом треугольников. Штрихи (координаты — доли карты): `line`, `circle`, `arc`,
  `dots` (пунктир), `stars`, `tpl` (контур шаблона, можно зеркально), `wave`. Линии — 4-связный Брезенхэм (без
  диагональных щелей). **Закрытые контуры получают проходы автоматически**: поиск в ширину «пересечь стену = 1,
  пройти свободную = 0», для каждой недостижимой области вскрывается кратчайший путь сквозь стены. Площадка у старта
  всегда свободна. Сцены проходятся на 100% — после расчистки остаётся готовая картина. Проходы — шириной 3 клетки
  (с v0.41: в щель в одну клетку шары попадали редко, и отсеки картины расчищались очень долго); старт «Сада» —
  в открытом небе, рост жизней «Сада» и «Кошачьего двора» вдвое меньше (после переноса старта к краю дальние квадраты
  стали втрое крепче — у бота «Сад» шёл 45 мин вместо 11; теперь ~20).
  Сцена — **цельная картина**: один крупный сюжет, линия горизонта связывает всё, детали взаимодействуют с главным
  объектом (не россыпь значков). Старт — на переднем плане (`map["start"]`), чтобы главный рисунок в центре
  не стирался площадкой старта.
  - «Сад» — «Ночной сад», овал 120×150: дом с трубой и дымом, окнами и дверью, большое дерево, месяц и звёзды над
    холмами (горизонт уходит за дом и дерево), забор с калиткой, котом и цветами, тропинка от двери к зрителю.
  - «Кошачий двор» — скруглённый квадрат 200×200: большой дом (крыша, труба, окна, арочная дверь), забор с котом,
    дерево, верёвка с бельём от дома к дереву, солнце и облака; на переднем плане клубок с ниткой, миска, рыбья
    косточка, дорожка из плиток.
  Формат сохранения карт — ver 7 (начатые «Сад» и «Кошачий двор» начнутся заново). Тест `test_scene_maps`.
- **Раскладка картинок — узор вокруг старта** (`game.gd → _layout_slot`, поле `layout` карты): карта делится на
  регионы `region×region`, картинка ставится по центру региона, размер 70% → 95% региона от центра к краю,
  на левой половине картинки зеркальные (карта симметрична). Узоры: `rings` — концентрические кольца, в каждом свой
  мотив (каждое третье кольцо пустое); `rays` — 8 лучей; `spiral` — 3 рукава; `checker` — шахматка;
  `mosaic` — сетка с чередованием мотивов. Сад — mosaic, Кошачий двор — rings, Горы — rays, Океан — spiral,
  Ночь — rings, бесконечные — по номеру. Регион со стартом пустой. (До v0.18 — случайная россыпь.)

## 3а. Прогрессия (с v0.20)

**Внутри уровня сбрасывается всё**: монеты, шары, уровни урона/скорости, U-баллы и деревья умений шаров.
**Между уровнями растёт только «Наследие»** — постоянные улучшения за ★. Ветка «Арсенал» (открытие типов за ★)
убрана в v0.26: типы открываются внутри уровня за 1 U; потраченные на неё ★ возвращаются при загрузке.

- **U-баллы уровня**: в среднем 25 до цели уровня (шанс на миллион = 25 / цель × 10⁶, ×1.2 за уровень «Поиска U»;
  в полостях картинок ×2). Тратятся на **дерево умений** каждого шара (вкладка «Умения» в прокачке):
  `0 основа (+20% урона, 1 U) → ветка умения типа I/II/III (2/3/4 U; уровень умения 2/4/5) и ветка скорости
  I/II/III (+10% скорости за узел, 2/3/4 U) → ★ суперспособность (6 U, нужны обе ветки)`. Сохраняется с уровнем.
- **★ звёзды** за выполненную цель уровня: впервые — 3 + номер уровня (с нуля: Лужайка 3, Сердце 4, Сад 5…),
  повторно — 1. Тратятся в **«Наследии»** (кнопка в меню). Ветки — цепочки (узел требует предыдущий):
  | Ветка | Узлы |
  |---|---|
    | Казна | Бонус монет (+10%, без предела, 1+ур.★) → Стартовые монеты (30·3^ур., до 5, 2+ур.★) |
  | Сила | Урон (+10% всем шарам, без предела, 1+ур.★) → Золотая лихорадка (+3 с, до 5, 2+ур.★) |
  | Удача | Поиск U (+20%, до 5, 2+ур.★) → Стартовые U (+1, до 5, 2+ур.★) |
  | Старт | Стартовые шары (+1 обычный, до 5, 3+ур.★) → Золотые квадраты (+20%, до 5, 2+ур.★) |
- **Профили**: 3 отдельных прохождения (`user://slot1..3/` — save.json и карты). Экран «Профили» из меню:
  выбрать, начать новую игру, удалить. Общие на все профили настройки — `user://settings.json` (язык, громкость,
  вибрация, экономия, экран, текущий профиль). Старое сохранение (один профиль в корне `user://`) переносится
  в профиль 1: пройденные карты → ★ (по формуле первого прохождения), открытые типы остаются, «Мастерство» → ★.

## 4. Шары (с v0.26 — из pixel-rikoshet, «Глубинный пиксель»)

Шесть шаров с ясными ролями, перенесены из pixel-rikoshet вместе с прокачкой и балансом. Внутренние id прежние
(на них держатся сохранения), имена и поведение новые. Порядок как там: orange, pink, red, green, banner, golden.
Антониевый, Гесиевый, Никитиевый названы автором pixel-rikoshet в честь друзей; в переводах — в духе элементов
(Antonium, Gesium, Nikitium).

| id | Шар | Роль | База |
|---|---|---|---|
| basic | Пронизывающий | бьёт клетку и отскакивает, открыт с начала | урон 1, 8.25 кл/с, пуск от 4 |
| sniper | Гесиевый | быстрый — чаще бьёт | урон 1, 16.5 кл/с |
| splash | Никитиевый | удар по открытым соседям (радиус 1) — 25% силы | урон 1 |
| poison | Антониевый | сам не бьёт, только отравляет; яд копится тиками | тиков 1, 1 тик/с, 1 HP за тик |
| banner | Знаменосец | шары в его круге (3 клетки) бьют на 30% сильнее ещё 1 с | урон 1 |
| pierce | Отбойник | сильный удар для крепкой породы | урон 8 |

- **Открытие типа** — внутри уровня за 1 U, в любом порядке (кнопка «Открыть · 1 U» на карточке).
- **Цена пуска** (как в pixel-rikoshet): `(база + 5·n)·1.12ⁿ`, n — сколько шаров типа куплено; база 4 у
  Пронизывающего, 50 у остальных. Мягкий потолок около 60–70 шаров одного типа: основные монеты уходят в прокачку.
- **Ветки за монеты** (без потолка): «Скорость» +20% от базы за уровень (предел шара 50 кл/с), «Сила удара» +1
  (у Отбойника +3); у Антониевого «Количество тиков» +1 и «Частота тиков яда» +0.5/с; у Знаменосца «Радиус ауры» +1
  клетка и «Длительность бафа» +0.5 с. Цены — заданные в каталоге (50, 112, 240…), дальше каждая ×1.7.
- **Яд**: клетка считает оставшиеся тики, каждый удар Антониевого прибавляет тики; частоту задаёт первый отравивший.
  Тик снимает 1 HP × «Наследие» × лихорадка. Разбитая клетка яд теряет.
- **Аура Знаменосца**: раз в 0.1 с шары в круге получают бафф (+30% урона) на время удержания; поиск через сетку
  с шагом в радиус — без перебора «каждый с каждым». Знаменосцы друг друга не усиливают. Круг виден тонкой линией.
- **Бонусы стаи** (идея автора pixel-rikoshet): за 5, 10, 20…80 купленных шаров типа (9 ступеней) все шары получают
  его особенность: Пронизывающий +5% монет, Гесиевый +5% скорости, Никитиевый +5% удара по соседям,
  Антониевый +5% урона ядом (каждый удар оставляет тики), Знаменосец +5% урона, Отбойник +1 к каждому удару — за
  ступень. Строка в карточке: «Бонус стаи 2/9: +10% монет · до следующей ещё 10».
- Дробные доли (удар по соседям, яд от бонуса) округляются случайно, в среднем точно.
- **Следующие этапы переноса**: эволюции (по две на шар за 5 и 10 U, ветки без потолка, уровень N стоит N U) —
  вкладка «Эволюции» в прокачке; затем карты-рисунки в стиле pixel-rikoshet (свои, не копии).


### Эволюции (с v0.27, из pixel-rikoshet)

С v0.43 прокачка — **вкладки шаров и одна компактная карточка** (с v0.44 вкладки внизу, над «Вернуться к игре»,
а каждая эволюция — на своей подложке, купленная — с зеленоватой рамкой) выбранного шара (открывается шар,
выбранный в игре). На вкладке — значок, число шаров (у закрытого — замок и «1 U») и зелёный счётчик того, что можно
купить прямо сейчас (`_affordable`). Карточка: заголовок с уроном «за уровень · в секунду»; описание шара — всегда целиком (с v0.45; до этого — в одну строку с «i»); бонус стаи — полоской («Стая 2/9», прогресс до следующей ступени, что даёт сейчас); улучшения за
монеты и ветки эволюций — одинаковые строки «название · 16.3 → 18.2 кл/с · [цена]» (`_upg_row`, единица один раз —
`_arrow`); некупленная эволюция — название, описание и кнопка ◆, купленная — заголовок с ✓, описание (с v0.45) и строки веток.
Кнопки цены неактивны, если не хватает. Остальные карточки построены, но скрыты (`_open_upg_tab`). Тест `test_upgrade_tabs`.
До v0.43 (с v0.28) прокачка была **одной страницей без вкладок**: в карточке шара описание, бонус стаи, ветки за монеты,
а ниже его эволюции (у закрытого шара — «Открыть · 1 U»). Все подписи — значения с единицами
«сейчас → после покупки» («Радиус разведки: 2 кл → 3 кл», «Частота молний: 0.25/с → 0.5/с», «Боевой клич: 10 с → 9 с»,
«Скорость: 8.2 кл/с → 9.9 кл/с»), номеров уровней нет; на пределе — «(макс.)». Формат — `_ev_text`, `_ev_caption`,
`_track_caption`; тест `test_upgrade_captions_values`.
**Предел ветки** (с v0.35): если следующий уровень не меняет значение, которое видит игрок, — подпись «…: 50 кл/с (макс.)»,
кнопка «макс.», покупка ничего не списывает (`_track_maxed`, `_ladder_maxed`). Значения считаются по-настоящему:
скорость — с потолком `MAX_SPEED` (50 кл/с), урон — с округлением; у веток эволюций есть `max` (скидка
«Массового производства» — до 50%), «Предел разгона» упирается в потолок скорости. До v0.35 скорость за монеты
качалась бесконечно, хотя после потолка ничего не давала, а деньги списывались. Тест `test_upgrade_caps`. У каждого шара две эволюции; покупка за U уровня: первая 5 U, вторая — 10 U
(`EVO_COST`, `EVO_LATER_MULT`). Каждая открывает две бесконечные ветки за U: уровень N стоит N U (до 40,
`LADDER_MAX`), значение = `base + step·уровень` (`GameData.EVOS`). Всё внутри уровня: на новом уровне эволюции
и ветки начинаются заново; «Наследие» остаётся сверху. Сохраняются с уровнем (`evo`, `elvl`, `extra`).

## 4а. Баланс и темп

**v0.27 (с эволюциями, бот):** Лужайка 2.3 мин, Сердце 2.3, Сад 4.0, Кошачий двор 8.3, Горы 23.5, Океан 25.3;

на карту считаются за секунды. **Меняешь экономику — прогони симулятор и обнови таблицу.**

| Сад | 4.2 | 4 с |
| Кошачий двор (50 тыс.) | 8.3 | ~30 с |

## 4б. Звук и вибрация
- Музыка и звуки синтезированы кодом: `tools/gen_audio.py` → `audio/*.ogg` (numpy + soundfile, внешних ассетов нет).
  Музыка — бесшовный луп ~46 с (84 BPM, ля минор Am–F–C–G: пэд, щипковое арпеджио Карплуса — Стронга, бас, мягкие
  ударные, колокольчики, свёрточная реверберация), 761 КБ. Звуки: hit, break, launch, aim, u, gold, buy, goal, tap,
  finale (3–17 КБ).
- Автозагрузка `Sfx` (`scripts/audio.gd`): шины Music (−8 дБ) и SFX (−2 дБ); частые звуки ограничены по частоте
  (удар ≤ 14/с, разрушение ≤ 16/с), высота тона слегка варьируется; нажатия любых кнопок озвучиваются автоматически.
- **Мини-вибрация** 40 мс в момент начала прицеливания (15 мс на многих телефонах не ощущались) (`GameData.vibrate`). На Android нужно разрешение
  `permissions/vibrate=true` в экспорт-пресете (до v0.18 его не было — вибрация не работала).
- Настройки: ползунки громкости «Музыка» и «Звуки игры» (0–100%, 0 — выключено), «Вибрация»; общие на все профили.

## 4в. Статистика уровней (с v0.30)
Время уровня (`play_time`) идёт, пока открыта игра на этом уровне (в свёрнутом виде не идёт), сохраняется с уровнем
и в сводке профиля (`map_states[id].time`). При выполнении цели — запись в `GameData.map_stats[id]`:
время первого прохождения, лучшее, число прохождений; в сообщении о цели — «Время: 17:32». В меню у карты:
«Пройдено за 17:32 · лучшее 15:10 · сейчас 8:41». Тест `test_map_stats`.

## 4г. Статистика шаров уровня (с v0.31; с v0.46 — расширенная)
С v0.46 в карточке шара — блок «Статистика» на своей подложке: урон за уровень, урон в секунду **за 60 с** (окно
`DPS_WINDOW` = 60, было 10 — значение сильно прыгало) и на один шар (урон в секунду ÷ число шаров типа, вместе с
залпами Дробовика). Цифры из заголовка карточки убраны.
В карточке каждого открытого шара в окне прокачки: «Нанесено урона: 12.3K · 154/с за 10 с». Урон засчитывается
типу шара в `_damage` (прямые удары, удар по соседям, яд, молнии, прошивка, бурение Клеща — всё, где известен шар);
среднее в секунду — по кольцу из 10 односекундных корзин игрового времени (`dmg_win`, `_dps`), в первые 10 с уровня —
за прошедшее время. Итог (`dmg_total`) сохраняется с уровнем, на новом уровне начинается с нуля.
Тест `test_ball_damage_stats`.

## 5. Языки

- 16 языков: English, Русский, 简体中文, हिन्दी, Español, Français, العربية, বাংলা, Português (BR), Bahasa Indonesia,
  Deutsch, 日本語, Türkçe, 한국어, Tiếng Việt, Italiano. Выбор — «Настройки»: сетка 3 колонки,

  иначе английский. `zh_*` → 简体中文 (в т. ч. zh_TW), `pt_*` → португальский (Бразилия). Пока игрок не выбрал
  язык вручную (`lang_choice == ""`), язык определяется заново при каждом запуске. В save.json хранится только
  явный выбор (`lang_choice`); старый ключ `lang` (до v0.12 записывался автоматически) игнорируется.
- Ключ перевода — русский текст в коде: `tr("Выстрел · %s")`. Переводы — `scripts/lang/<код>.gd` (`const T`),
  реестр и названия — `scripts/i18n.gd`; при старте все таблицы регистрируются в TranslationServer.
  Названия и описания шаров/карт хранятся по-русски и переводятся при показе. Название игры в заголовке —
  «BALL BREAKER» на всех языках, кроме русского.
- **Запасной язык проекта — русский** (`internationalization/locale/fallback="ru"`): иначе русский режим
  показывал бы английский (баг v0.8).
- **Шрифты**: Rubik покрывает латиницу и кириллицу; иероглифы, хангыль, арабское письмо, деванагари и бенгальское
  письмо берутся из системных шрифтов (`allow_system_fallback`, на Android — встроенные Noto). APK не растёт.
- **Арабский — справа налево**: интерфейс зеркалится автоматически (layout direction по локали). Фишки с числами
  («×2 · 46») принудительно слева направо.
- Название приложения: «Шароломка» для русской системы, «Ball Breaker» для остальных.
- Новая строка интерфейса → `tr("...")` + запись во **все** `scripts/lang/*.gd`. Тест `test_translations_complete`
  падает, если перевода нет, он пустой, плейсхолдеры не совпадают или в таблице остался неиспользуемый ключ.
  `test_foreign_ui` проверяет, что ни на одном языке, кроме русского, в интерфейсе нет кириллицы.

## 5а. Настройки (экран «Настройки» из меню)
Внизу главного меню — номер версии (`application/config/version`; CI подставляет тег, для сборок без тега — `dev-<sha>`):
по нему видно, какая сборка запущена.
Сверху ползунки громкости «Музыка», «Звуки игры», переключатели «Вибрация», «Экономия батареи» (30 FPS), «Не блокировать экран» (флаг окна KEEP_SCREEN_ON: пока игра открыта, экран
не затемняется и телефон не блокируется; применяется заново при каждом возвращении в игру); ниже — язык;
внизу закреплены «Сбросить весь прогресс» (с подтверждением) и «Назад». Список прокручивается пальцем, кнопки сброса и «Назад» закреплены внизу. Всё в save.json.

## 6. Время и сохранения

- Игра идёт, пока открыта прокачка. **В свёрнутом виде игра на паузе** (офлайн-прогресса нет — решение владельца).
- Сохранение: каждые 20 с, при сворачивании/закрытии и выходе в меню.
- Запись **атомарная**: во временный файл `*.tmp`, затем переименование — если телефон выключится посреди записи,
  останется прежнее целое сохранение. Повреждённые файлы не роняют игру (поля проверяются по типу).
- Общее сохранение при частых событиях (найден U-балл) — отложенное, не чаще раза в 3 с; при сворачивании — сразу.
- `user://save.json` — общее: U, открытые типы, перки, суперы, открытые карты, пройденные цели, настройки,
  `map_states[id] = {"saved": true}`.
- `user://map_<id>.bin` (`store_var`) — карта: `ver: 5`, монеты, разбито, цель выполнена, шары, уровни,
  `chunks: {индекс_куска: [zstd(hp int32×1024 + vis byte×1024 + kind byte×1024), размер]}` — только изменённые
  куски; с v0.15 в куске хранятся и типы клеток, поэтому открытая часть не зависит от генератора
  (старые куски без типов тоже читаются),
  `balls: [[тип, x, y, vx, vy], …]`, `last_launch`, `aim`, `selected`.
  При смене формата повышай `ver` — старые сохранения карт отбрасываются (U и перки сохраняются).
- **Шарики сохраняются** (тип, позиция, направление): после «Продолжить» каждый летит дальше со своего места.
  Сохраняются также место последнего выстрела, направление и выбранный тип. Если шаров в сохранении меньше,
  чем куплено (старое сохранение), недостающие вылетают из старта.

## 7. Архитектура

```
scripts/
  game_data.gd   автозагрузка GameData: типы шаров (TYPES), U, перки, сохранение save.json, тема UI, fmt()
  maps.gd        карты (get_maps) и шаблоны картинок (templates), геометрия многоугольников
  game.gd        игровая сцена: мир, физика, отрисовка, камера, ввод, интерфейс
  chunk.gd       кусок мира 32×32: hp, kind, vis, solid, узел отрисовки, кэш сохранения
  ball.gd        шарик: позиция, скорость, тип, заработок, кулдауны
  i18n.gd        список языков, их названия, выбор языка по системе
  lang/*.gd      переводы (ключ — русский текст из tr()), по файлу на язык
  audio.gd       автозагрузка Sfx: музыка, звуки, шины, ограничение частоты
  touch_scroll.gd  прокрутка списков пальцем, даже с кнопок (прокачка, меню)
  icons.gd       иконки, нарисованные кодом (монета, кристалл, меню, сброс, стрелка, угол, замок, шарик)
  main_menu.gd   меню карт и экран настроек
scenes/          game.tscn, main_menu.tscn — тонкие, всё строится в коде
tools/gen_audio.py  генератор музыки и звуков → audio/*.ogg
tests/           test_runner (логика, headless), ui_playtest (касания + скриншоты, нужен рендер)
fonts/Rubik.ttf  шрифт (OFL), вес 500 и 700 через FontVariation
```

### Мир кусками (game.gd)
- `chunks` — плоский массив `cw × chh` (до 313×313 для 10000×10000), элемент — `chunk.gd` или null.
  Кусок создаётся лениво (`_get_chunk`): при открытии клеток, физике, загрузке сохранения.
- Генерация куска: маска картинки из `_region()` (кэш `region_cache`) → стена; иначе квадрат с hp по формуле;
  поверх — данные из сохранения.
- Сид карты — `_seed_of(id)`: собственный djb2 (значения совпадают с `hash()` Godot 4.3, зафиксированы тестом),
  чтобы обновление движка не меняло карты относительно сохранений.
- `cell id = y · W + x`; кусок `(x>>5) + (y>>5)·cw`, индекс в куске `((y&31)<<5) | (x&31)`.

### Физика (game.gd → `_move_ball`)
- Непрерывные столкновения: луч из центра шарика против клеток, расширенных на радиус (AABB, slab-тест),
  шаг до 1 клетки, до 24 итераций за кадр. Нормали осевые: отражение = смена знака vx/vy.
- Быстрый путь: если кусок пустой (`solid == 0`), шарик летит до края куска за один шаг.
- Защита от залипания: >3 столкновений подряд на нулевом расстоянии — выход до следующего кадра.
- Края мира — отражение. Порядок кадра: `_sim(delta)` → яд → кулдауны.

### Отрисовка
- Каждый кусок — свой Node2D; перерисовываются только «грязные» куски в пределах экрана — **не чаще 10 раз в секунду**
  и не больше 12 за раз (ограничение потерялось в v0.3, восстановлено ревью v0.15, проверяется тестом).
- Слой прицела и подсказок перерисовывается только пока он на экране (+1 кадр, чтобы стереть).
- Стены: цельная белая фигура — светлая фаска сверху/слева, тёмная снизу/справа, тень на пол, швы между кубиками.
- Квадраты: цвет по log10(hp) (зелёный → жёлтый → красный → фиолетовый), светлая полоса сверху, тёмная снизу.
- Шарики: один Node2D, `draw_texture_rect` с одной текстурой (Godot склеивает в один вызов).
  **MultiMesh не использовать** — на Android в Compatibility шары не отображались (v0.3).
- Интерфейс в CanvasLayer → тему нужно задавать `ui_root.theme` явно (через CanvasLayer тема не наследуется,
  из-за этого в v0.4 кнопки были стандартными).

### Интерфейс и тема
- **«Вернуть шар»** (с v0.37, бывший «Сброс»): надпись постоянная и всегда в одну строку — шрифт кнопок нижнего
  ряда ужимается под ширину (`_fit_button_text`, от 23 до 15), высота ряда не меняется. Состояние — оформлением:
  готова — обычная; включена — акцентная заливка, а шар, который вернётся (бездельник выбранного типа), пульсирует
  голубым кольцом; перезарядка — кнопка неактивна, фон заполняется слева направо (`_layout_reset_fill`: плашка размером с кнопку
  внутри «окна» растущей ширины — видна с первой секунды, от самого края; до v0.41.2 появлялась лишь через ~5 с). Повторное
  нажатие выключает режим. Тесты: `test_recall_button`, высота нижней панели в `test_bottom_bar_fits`.
- **Тип шара читается по форме** (с v0.36), не только по цвету: `Icons.ball_type` рисует силуэт каждого типа один раз
  при запуске (сглаживание по 3×3 подвыборкам, запас места вокруг шара `BALL_K` = 1.5). Пронизывающий — круг с бликом;
  Гесиевый — круг со шлейфом против полёта (рисуется на лету); Никитиевый — пунктирное кольцо; Антониевый — сам шар-капля
  (с v0.39; кончиком против полёта, как шлейф Гесиевого, — с v0.40, `_drop_rot`; белая капля внутри круга не читалась); Знаменосец — флажок; Отбойник — толстый белый обод, тёмная сердцевина и на 25% крупнее (различим и в точку).
  На фишках и в карточках — значки `ui_icons` (`Icons.ball_type(..., ui = true)`): у Гесиевого шлейф нарисован в самом
  значке (на поле он живой, по полёту), флажок Знаменосца крупный (с v0.38; до этого Гесиевый на фишке был просто кругом,
  а флажок не читался). Тест проверяет, что значки на фишках различаются у всех пар типов. Нажатие на фишку на 1.2 с подсвечивает ободом все шары
  этого типа на поле. Тест `test_ball_markers`.
- Подпись прогресса — числа и проценты: «1.2K из 18.2K · 7%»; после цели на больших картах — «Разбито 352K · 195%»
  (процент от цели). Процент округляется вниз (100% — только при полной расчистке), до 10% — с одним знаком.
  Подпись обрезается, а не раздвигает панель; тест `test_progress_label` проверяет, что она помещается целиком.
- Верхняя панель неподвижна: плашки монет и U — фиксированной ширины под самую длинную запись числа
  («888.8Qa», «8888»), цифры табличные (OpenType `tnum` жирного Rubik, `GameData.tnum_font()`), поэтому при смене
  чисел блоки не меняют ни ширину, ни положение. Тест `test_top_bar_stable`.
- Размеры шрифта (вьюпорт 720 px по ширине): основной 26, подписи (`Muted`) 21, заголовки (`Title`) 29;
  в окне прокачки — своя тема крупнее: 28 / 23 / 32, узлы дерева 23. Сетка языков в настройках — 2 колонки.
  Тесты проверяют, что ни панели, ни узлы дерева, ни подписи цен, ни кнопки языков не вылезают и не обрезаются
  (в т. ч. на немецком и вьетнамском).
- Окно прокачки прокручивается пальцем, даже если палец лёг на кнопку: своя обработка в `game.gd → _input`
  (в Godot 4.3 кнопка захватывает касание и ScrollContainer его не получает). Сдвиг по вертикали > 14 px —
  прокрутка, нажатие кнопки под пальцем отменяется: кнопка временно выключается до отпускания пальца
  (`scripts/touch_scroll.gd`). В v0.26 нашлось, что прежний способ (синтетическое «отпускание мыши») не работал —
  тест раньше начинал прокрутку с неактивной кнопки и проходил впустую; теперь начинает с активной.
- Тема в `GameData.make_theme()`: варианты `AccentButton` (синяя основная), `ChipButton` (фишка, выбранная — рамка),
  `Card`, `Pill`, `Muted`, `Title`. Цвета — константы `C_*` в game_data.gd.
- Иконки — только из icons.gd (в шрифте нет стрелок/значков). Валюта — нейтральные монеты (значок монеты из icons.gd, без символа валюты).

## 8. Производительность и батарея
- Бюджет: 200 шаров на любой карте — симуляция < 4 мс/кадр на сервере CI (тест `test_performance_budget`;
  сейчас ~0.6 мс). Карта 10000×10000 грузится < 3 с (сейчас ~70 мс).
- 60 FPS по умолчанию, в меню «Экономия: 30 FPS». Меню — low processor mode. Экран гаснет как обычно
  (настройка «Экран: не гаснет»). Физический движок Godot не используется.

## 9. Тесты и CI
- `tests/test_runner.tscn` — инварианты (см. список в файле): генерация карт, достижимость, каждый тип шара
  не уходит в туман/стены и даёт прогресс, туман, экономика (монеты = снятые жизни), счётчики кусков,
  выстрел, рогатка (выстрел из точки нажатия/отмена/касание/туман/округление угла), жест удержание/сдвиг, точка вылета, камера до края,
  сохранение/загрузка (включая позиции шаров), прохождение Лужайки, сброс-перезапуск бездельника, огромная карта, производительность, полнота перевода, язык по умолчанию,
  русский интерфейс в русском режиме, отсутствие кириллицы в английском интерфейсе. Код выхода = число упавших.
- `tests/ui_playtest.tscn` — касаниями: меню → игра → рогатка с удержанием (выстрел и отмена) →
  перемещение карты одним пальцем → щипок → кнопка «Выстрел» →
  сдвиг карты → прокачка → покупка → сброс → меню → «Продолжить» → «Настройки» → English → игра и прокачка
  на английском → настройки, прокачка и игра на немецком, китайском, арабском, хинди, японском.
  Скриншоты в `build/screens/` (в CI ставятся шрифты Noto, чтобы все письменности отрисовались). Тесты принудительно ставят русский язык.
- Тесты логики идут в окне 720×1280, как у телефона: в режиме без экрана окно по умолчанию 64×64 и видимая область
  1280×1280 — до v0.32 проверки «не вылезает за экран» шли на ширине 1280 и пропускали реальные переполнения.
- **Ошибка скрипта внутри теста прерывает его без FAIL** (в Godot нет исключений) — CI считает падением любой
  `SCRIPT ERROR` в выводе тестов. Локально тоже смотри на SCRIPT ERROR.
- UI-тест в CI идёт дважды: 720×1600 (20:9) и 720×1280 (16:9, длинные списки, прокрутка) —
  скриншоты в `screenshots` (`build/screens`, `build/screens_16x9`).
- Хаос-тест: тысяча случайных действий игрока на двух картах с проверкой инвариантов после каждого.
- Тесты v0.18: раскладки (мотив кольца, зеркальность, детерминированность, разнообразие узоров), звук (загрузка,
  выключатель, ограничитель частоты, озвучка выстрела), вибрация (только при включённой настройке), граница.
- Тесты баланса: темп первых карт (бот), финал добивает квадраты, вехи урона, бонус монет, лихорадка,
  нижняя панель влезает в экран при всех 5 типах.
- GitHub Actions (`.github/workflows/build.yml`): тесты логики и UI-тесты (xvfb) → сборки Android/Windows/Linux →
  на тег `v*` GitHub Release. Скриншоты UI-теста — артефакт `screenshots` каждого прогона.
- Android подписывается ключом из секретов `ANDROID_KEYSTORE_BASE64/USER/PASSWORD` (alias `sharolomka`),
  versionCode = номер прогона, versionName = тег.
